## WhatsApp

**Implementation:** the WhatsApp template uses CopilotKit Channels’ direct Meta adapter with OpenAI Agents SDK planning and Auth0 account linking/CIBA approval. It retains a separate install, runtime, and persistent data file. Twilio is removed. The public webhook validates the business phone-number ID and forwards unchanged signed bytes to the SDK; outbound replies use its renderer. Meta-bound state rejects old provider data without overwriting it. SDK receipt precedes asynchronous app persistence, so an HTTP 200 does not establish durable processing.

**Current local verification:** clean `npm ci --prefix apps/whatsapp`, the app’s typecheck, and all **35 tests** passed on Node 22.23.2. Independent spec review reproduced the tests and typecheck and confirmed `@ag-ui/client` 0.0.59 is deduplicated with Channels 0.9.2 / runtime 1.70.3. Tests use the actual Meta adapter and runtime with local Intelligence, Graph, Auth0/JWKS, and OpenAI fixtures. They cover signature/challenge handling, raw-byte preservation, destination isolation, status events, linking, approval rejection, exact saved actions, duplicates, uncertainty, cooldown, the reply window, and restart/history/status. These fixtures are not live phone evidence. The app-scoped install uses `legacy-peer-deps` for unused legacy connector conflicts; eight transitive audit findings remain (seven moderate, one high).

**Account setup:** a development Auth0 tenant accepted the Regular Web Application, authorization code/CIBA grants, RS256 API, and the app’s user-delegated `create:requests` grant. A requester role contains that permission; the Guardian factor and push-only CIBA settings are enabled, and the demo tenant requires MFA at login. [Actual settings screenshots](template-walkthroughs/whatsapp/README.md#1-prepare-the-auth0-application-and-device) document these steps. Application-user role assignment, Guardian device enrollment, and live approval are not yet verified. Meta developer sign-in and test-number setup remain pending.
