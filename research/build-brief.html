The brief

Read it once, then design against the clock

Most agents still wait inside a separate chat window. The challenge starts somewhere else: build an agent that belongs in a place people already work, talk, and live — and make it meaningfully more useful because of that context.

Four example surfaces, explicitly not separate tracks: at work (Slack, Teams, email, docs, calendars, tickets), in your pocket (messaging, mobile, notifications), on the web (browsers and software where an agent can research, navigate, transact), and in the room (voice, vision, wearables, robotics).

Every team submits five things: a title, a written description covering who it's for and why the context matters, a public GitHub repo, a two-minute demo video, and a public social post tagging sponsors. Every eligible project from all 51 cities enters one global review.

The design constraint that dominates everything else is the build window. Doors open at 10:00, but hands hit keyboards at 11:15 and submission closes at 17:00 with demos eating the hour before. A starter kit that spends an hour on OAuth apps, tunnels, and Docker has taken a quarter of the day.

The Context Ladder

The kit's conceptual spine — three levels of belonging

The previous kit organized itself around the generative-UI spectrum. This one needs its own axis, and the challenge statement hands it over: because of that context. That's a ladder, and it climbs.

  1. 01

    Reachable

    The agent is addressable where you already are. Mention it, it answers.

    Table stakes. Every submission in every city clears this rung.

  2. 02

    Situated

    It reads the surface's context without being told — thread history, the document you're inside, who is asking, which channel, what happened an hour ago.

    The test: delete the context and ask again. Same answer? You're still on rung 01.

  3. 03

    Native

    It acts and renders in the surface's own idioms — Block Kit cards, approval buttons, reactions, push notifications — and its side effects land where the work actually lives.

    The test: does it look like it belongs, or like a chat window wearing a costume?

Rung 03 is where a global review separates submissions. The kit's job is to make rung 01 free, rung 02 easy, and rung 03 obvious.

One agent, every surface

The thesis, and what AG-UI is for

Every app points at the same agent over AG-UI. Swapping surfaces becomes a config change instead of a rewrite — which means a team can demo their agent in Slack and on a phone inside the two-minute video, while 51 cities submit chat bots.

packages/
  agent-core/        ONE AG-UI agent. Tools, model routing, memory.
  context-kit/       thread history, participants, files, locale

apps/
  channel-slack/     @copilotkit/channels → managed Slack      [at work]
  channel-teams/     same listener, Teams adapter              [at work]
  web/               Next.js + CopilotKit generative UI         [on the web]
  mobile/            Expo + @copilotkit/react-native            [in your pocket]
  voice/             OpenAI Realtime over WebRTC                [in the room]
  plugin/            MCP server + optional ChatGPT UI           [ChatGPT]

agent-core stays framework-agnostic: CopilotKit's BuiltInAgent by default — zero Python, zero extra process — with documented one-file swaps to LangGraph, Mastra, Pydantic AI, CrewAI, or Google ADK. The prior kit forced a Python uv plus langgraph dev process on everyone, and that cost isn't justified at minute zero.

Why Channels needs no tunnel

Delivery runs on two legs, and neither is Socket Mode. The provider posts inbound HTTPS to a CopilotKit-hosted request URL — Slack signed with a signing secret Intelligence holds, Teams with a Microsoft-signed bearer JWT. Then Intelligence dials your runtime over an outbound websocket authenticated by your project key. No ngrok, no public URL of your own, no app-level token. On a 255-minute clock that is the single biggest advantage the kit has over a raw Bolt app.

The flip side: the listener is a long-running worker, so it deploys like a queue consumer — Railway, Cloud Run with min-instances ≥ 1, Fly, plain Docker. not serverless Say so plainly in the README, or someone loses their 15:30 demo to a Vercel function.

Setup tiers

Cumulative, and each one ships something demoable

Tier 0 — it answers

5 min · one credential

Clone, install, drop in OPENAI_API_KEY, npm run dev. Web app and agent core, replying. No Docker, no Postgres, no provider app. Arrive at 11:15, write product code by 11:22.

Tier 1 — it lives in Slack

+15 min · zero tunnel

npx copilotkit@latest channels setup installs a skill and prints a prompt your coding agent drives. Adds INTELLIGENCE_API_KEY and CHANNEL_CODE. Create the Channel before the Slack app — the wizard generates the manifest.

Tier 2 — it does real work

opt-in · one file each

Exa for grounded search, Ambiguous for a whole workplace, Trigger.dev for durable work, Auth0 for out-of-band approval, mcpd for declarative tools, OpenRouter for fallback. Pick two, not six.

Keep the prior kit's two best habits verbatim: a predev pre-flight check that fails loudly with a numbered list of what's missing, and an .env.example where every variable carries a comment saying where to click plus a stub-replace-me placeholder so the app boots before credentials exist.

Known traps

Each one has already cost someone real time — seed the troubleshooting doc with all of them

  • looks greenchannels.ready() resolves on setup_required as well as online. Assert channels.status().overall === "online".
  • silentLifecycle breadcrumbs are emitted at warn while the runtime logger defaults to error. Run LOG_LEVEL=debug and watch for channel "<name>" requires setup.
  • raceTwo runtimes declaring one Channel name race per delivery, and the loser gets nothing. The tell is a Slack reply your terminal knows nothing about. One project per local runtime.
  • no eventWorkspace-installed is not the same as channel member — Slack emits no app_mention at all. /invite @Bot.
  • routingMentioned turns hit onMention, falling back to onMessage. Non-mentioned turns only ever reach onMessage. Verify with a channel mention first.
  • by designManaged Slack delivers no slash commands and no modal submissions. Code registering them compiles, starts, reports online, and never fires.
  • authlessSlack wants a signing secret; Teams wants a Microsoft-signed bearer JWT. Cross them and the app installs cleanly and authenticates nothing.
  • orderCreate the Channel before the provider app. The wizard generates a manifest already pointed at the right request URL; the kebab-case Code must match createChannel({ name }) character for character.
  • not brokenThe dashboard's "Agent run: —" and "AGENT: Not declared" are not failures. The Usage tab — completed turns, non-zero outbound — is what proves a round trip.
  • repoGitHub only inline-plays video uploaded through a comment box as a user-attachment. Raw repo files and release assets serve octet-stream with nosniff, so a committed <video> stays dead.

Open questions

Resolve before Saturday

  • The judging rubric and prize categories are unpublished — promised to builders before the day. If they land, re-check that the Context Ladder still aligns with what's actually rewarded.
  • Builder credits and promo codes are unannounced. Ship a CREDITS.md stub and fill it in at the 10:30 opening.
  • Local sponsor rosters differ. Keep sponsor content in per-file sections so a city can drop one without editing prose.
  • Managed Teams support needs a status check. Slack is the safe surface to demo.
  • Whether an official OpenAI or AI Tinkerers starter repo also ships — and whether this kit should complement it rather than compete.
